Cursor запускает собственный хостинг кода — и агентов, которые стартуют без репозитория

Инструменты Aug 17, 2026·Cursor

Август Cursor потратил на превращение редактора в инфраструктуру. Три релиза, которые вместе задают чёткое направление.

Origin: Cursor размещает ваш код

17 августа Cursor запустил Origin — встроенный хостинг репозиториев кода — в режиме ранней беты. Он синхронизируется с репозиториями GitHub в обе стороны в реальном времени, управляет pull request'ами через синхронизацию с GitHub и интегрируется с Vercel, Depot и Buildkite.

То, что ИИ-редактор выпускает собственный хостинг кода, — значимый шаг. Это означает, что агенту больше не нужно обращаться через границу API, чтобы прочитать историю, открыть ветку или управлять ревью.

Агенты без репозитория

27 августа Cloud Agents перестали требовать GitHub или любую стороннюю систему контроля версий для начала работы. Теперь агент создаёт репозиторий Origin в фоновом режиме, а результат работы позже можно преобразовать в постоянный репозиторий с выбранным именем и уровнем видимости. Включены предпросмотр в реальном времени в браузере и публикация через Vercel.

Это полностью убирает этап настройки: описываете задачу, получаете рабочий код с историей, а решение о том, заслуживает ли он статуса полноценного проекта, принимаете уже потом.

Машины с самостоятельным хостингом

2 сентября Cursor добавил машины с самостоятельным хостингом, позволяющие выполнять инструменты внутри собственной сети. Есть персональные машины и командные пулы, использование компьютера на Linux и Mac с управлением рабочим столом, а также поддержка AWS Lambda, Coder, Cloudflare, Daytona и Modal.

Это ключ к корпоративному сегменту. Многие организации не могут позволить агенту выполнять код на инфраструктуре стороннего поставщика, и это напрямую снимает данное возражение.

Почему это важно

Если рассматривать эти три изменения вместе, они переводят Cursor из статуса «ИИ-функции в редакторе» в место, где код живёт, выполняется и поставляется. А это также означает, что стоимость перехода на другой инструмент растёт: репозиторий в Origin, агенты, настроенные вокруг него, и выполнение на собственных машинах — это гораздо более серьёзное обязательство, чем просто редактор, который можно заменить.

Стоит взвесить, прежде чем использовать Origin как что-то большее, чем зеркало. Двусторонняя синхронизация с GitHub позволяет сделать это безопасно — оставить GitHub основным источником истины, а Origin использовать как рабочую копию.
