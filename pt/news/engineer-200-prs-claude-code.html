De 20 para mais de 200 PRs mesclados por mês: como um engenheiro trabalha com o Claude Code

Ferramentas Nov 3, 2026·The Pragmatic Engineer

A newsletter The Pragmatic Engineer promoveu um concurso de ensaios entre os leitores, e o texto vencedor, publicado em 3 de novembro, é um relato em primeira mão de como é programar com IA em velocidade máxima. O autor, Neil Kakkar, tem nove anos de experiência, incluindo Bloomberg e PostHog, e hoje é o primeiro engenheiro da Tano, uma startup de cerca de dez pessoas.

Os números

Em empregos anteriores, Kakkar mesclava de 8 a 20 pull requests por mês. Na Tano, ele entrega mais de 200, cerca de 11 vezes o que produzia na PostHog. Ele relata uma taxa de revert cerca de seis vezes menor, principalmente porque os problemas são corrigidos com um novo fix (fix forward), e um tempo mediano de menos de uma hora entre abrir um PR e mesclá-lo. O time inteiro mescla cerca de 30 PRs por dia.

O setup

Tudo roda no Claude Code. Cada engenheiro tem uma assinatura do Claude Max 20x; Kakkar estima que o uso dele custaria mais de US$ 8.000 por mês a preços de API. Ele trabalha no app desktop do Claude Code, com o navegador embutido, em vez da linha de comando, mantém de 3 a 5 tarefas em paralelo e deixa os agentes rodarem de uma a duas horas por funcionalidade, incluindo as próprias verificações e capturas de tela. Todo PR recebe uma revisão automática de um agente do Claude Code no GitHub Actions, com um agente de revisão mais aprofundado para mudanças arriscadas. Na maioria dos PRs, esse agente é o único revisor. O contexto de cada área do produto fica registrado em arquivos AGENTS.md para que os agentes consigam encontrá-lo.

O que deu errado

Ele lista as falhas sem rodeios. Um agente multiplicou valores monetários por 100, o que é errado para moedas como o dinar bareinita; o erro foi detectado depois do deploy e corrigido em menos de uma hora. Uma migration bloqueante de banco de dados em uma tabela grande parou a ingestão de dados. Outra migration sem salvaguardas pagou alguns criadores em dobro. Regras como essas agora estão nas instruções do agente revisor.

Os custos humanos também estão na lista: troca de contexto constante, menos pessoas que conhecem cada parte do código, design com cara genérica e esbarrar nos limites do plano quando os agentes ficam rodando em loop. A regra do próprio Kakkar é parar às 18h e deixar os dispositivos de trabalho no escritório.

A ressalva do editor

Gergely Orosz, que comanda a newsletter, acrescenta que, no setor como um todo, o volume de PRs mais ou menos dobrou desde janeiro, então este caso está muito acima da média, e que velocidade sozinha não prova que um produto está dando certo. Empresas maduras, argumenta ele, deveriam mudar seus processos com mais cuidado.

O que isso significa se você está escolhendo um agente de programação

O ganho veio do processo, não só da ferramenta. Contexto documentado, um revisor automático em cada PR e regras aprendidas com incidentes pesaram tanto quanto o modelo.

Considere os limites no planejamento. Até o plano mais alto do Claude se esgotava quando os agentes trabalhavam em loop, então confira a cota antes de planejar execuções durante a noite. Se você está comparando opções, veja Codex vs Claude Code e nossa lista de ferramentas de IA para programação.
