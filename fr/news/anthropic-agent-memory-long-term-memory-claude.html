Anthropic lance Memory pour les Claude Managed Agents

Tools Apr 18, 2026·Anthropic Blog

Anthropic a lancé Memory, un service géré qui dote les agents Claude d'une mémoire persistante d'une session à l'autre. Jusqu'à présent, chaque conversation d'agent repartait de zéro : tout ce que l'agent avait appris sur une base de code, un client ou un workflow disparaissait dès la fin de la session.

Ce qui change

Memory extrait les informations clés des conversations des agents et les ressurgit lorsqu'elles redeviennent pertinentes, au lieu de rejouer des transcriptions entières. L'effet concret se fait sentir sur la fenêtre de contexte — l'agent conserve ce qui compte sans porter tout l'historique, ce qui permet de garder un contexte allégé et un coût par exécution prévisible.

Memory est conçu comme une couche basée sur un système de fichiers : les entrées sont stockées sous forme de fichiers qui peuvent être exportés, gérés via l'API et soumis à des permissions. Chaque modification est journalisée, avec une piste d'audit par session et par agent, ce qui permet aux équipes d'annuler, de corriger ou de supprimer ce qu'un agent a retenu.

Disponibilité

Le service a été lancé en bêta publique sur la Claude Platform le 23 avril 2026, pour les Claude Managed Agents. Parmi les premiers utilisateurs cités par Anthropic figurent Netflix, Rakuten, Wisedocs et Ando, qui l'utilisent pour réduire le travail de configuration répété et limiter les erreurs dans les workflows de longue durée.

Parallèlement à cette annonce, Anthropic a ouvert un hackathon développeurs doté de 100K$ construit autour de Claude Opus 4.7, offrant 100K$ de crédits API et se déroulant du 21 au 28 avril.

Pourquoi c'est important

Une mémoire persistante, c'est ce qui distingue un chatbot d'un agent qui s'améliore dans son travail. Sans elle, chaque amélioration doit être injectée manuellement dans les prompts ; avec elle, un agent accumule des connaissances par lui-même et l'opérateur n'a plus à réexpliquer le même contexte. Pour les équipes qui font tourner des agents sur des files de support, de revue de code ou de traitement de documents, cela élimine la principale source de maintenance répétitive des prompts.

La piste d'audit compte tout autant que la mémoire elle-même : tout ce qu'un agent retient sur des clients ou des systèmes internes doit pouvoir être inspecté et supprimé avant qu'une entreprise n'accepte de le mettre en production.
