Cursor 3.4 Adds Multi-Repo Environments and Dockerfile-Based Setup for Cloud Agents

Tools May 13, 2026·Cursor Blog

Cursor released version 3.4 on May 13, 2026, introducing multi-repo development environments for cloud agents and automations, along with Dockerfile-based environment configuration.

Agentic dev environments

In Cursor 3.4, development environments for cloud agents can be configured from a Dockerfile, with support for build secrets and layer caching. Agents then take on environment setup within these containerized environments — described by Cursor as agent-led environment setup — allowing work to happen in isolated, reproducible environments that match production specifications.

Multi-repo environments

Multi-repo support lets cloud agents and automations work across multiple repositories within a single environment — useful for microservices architectures and monorepos where a feature change requires coordinated edits across several codebases. Cursor also supports running multiple agents in parallel on different tasks from a single workspace, a capability that predates version 3.4.

Cursor 3.3 recap and Bugbot billing change

Cursor 3.3, released May 7, 2026, had added PR review inside the editor — developers can open a pull request, view diffs, and receive AI-generated review comments without leaving Cursor or switching to GitHub. Announced May 11, 2026, Bugbot (Cursor's automated bug detection on commits and PRs) is moving from per-seat billing to usage-based billing. For existing customers, the change takes effect at their next renewal after June 8, 2026. Teams that rely heavily on automated bug scanning should review the new pricing ahead of that date.

Why it matters

Cursor 3.4 narrows the gap between AI-assisted coding and more autonomous software development workflows. The combination of Dockerfile-based environment configuration and multi-repo support means cloud agents can take on setup and coordination tasks that previously required manual orchestration across tools, terminals, and repositories. For engineering teams, this can reduce the overhead of preparing environments for agent-driven tasks.
