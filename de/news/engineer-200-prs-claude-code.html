Von 20 auf über 200 gemergte PRs im Monat: So arbeitet ein Entwickler mit Claude Code

Tools Nov 3, 2026·The Pragmatic Engineer

Der Newsletter The Pragmatic Engineer hat einen Essay-Wettbewerb unter seinen Lesern veranstaltet, und der Siegerbeitrag, veröffentlicht am 3. November, ist ein Bericht aus erster Hand darüber, wie KI-gestütztes Programmieren bei voller Geschwindigkeit aussieht. Der Autor, Neil Kakkar, hat neun Jahre Berufserfahrung, unter anderem bei Bloomberg und PostHog, und ist heute der erste Engineer bei Tano, einem Startup mit rund zehn Leuten.

Die Zahlen

In früheren Jobs hat Kakkar 8 bis 20 Pull Requests im Monat gemergt. Bei Tano liefert er mehr als 200, etwa das 11-Fache seines Outputs bei PostHog. Seine Revert-Rate sei ungefähr sechsmal niedriger, vor allem weil Probleme per Fix-forward behoben werden, und die mediane Zeit vom Öffnen eines PR bis zum Merge liege unter einer Stunde. Das ganze Team merged rund 30 PRs am Tag.

Das Setup

Alles läuft über Claude Code. Jeder Engineer hat ein Claude-Max-20x-Abo; Kakkar schätzt, dass seine Nutzung zu API-Preisen mehr als 8.000 $ im Monat kosten würde. Er arbeitet in der Desktop-App von Claude Code mit ihrem eingebauten Browser statt auf der Kommandozeile, hält 3 bis 5 Aufgaben parallel am Laufen und lässt Agents ein bis zwei Stunden pro Feature arbeiten, einschließlich eigener Checks und Screenshots. Jeder PR bekommt ein automatisches Review durch einen Claude-Code-Agent in GitHub Actions, für riskante Änderungen gibt es einen gründlicheren Review-Agent. Bei den meisten PRs ist dieser Agent der einzige Reviewer. Der Kontext zu jedem Produktbereich ist in AGENTS.md-Dateien festgehalten, damit die Agents ihn finden.

Was schiefging

Die Fehler zählt er ohne Umschweife auf. Ein Agent multiplizierte Geldbeträge mit 100, was für Währungen wie den Bahrain-Dinar falsch ist; das fiel nach dem Deploy auf und war innerhalb einer Stunde behoben. Eine blockierende Datenbankmigration auf einer großen Tabelle stoppte die Datenaufnahme. Eine weitere Migration ohne Absicherungen zahlte manchen Creators doppelt aus. Regeln wie diese stehen jetzt in den Anweisungen des Review-Agents.

Auch die menschlichen Kosten stehen auf der Liste: ständige Kontextwechsel, immer weniger Leute, die ein bestimmtes Stück Code kennen, generisch wirkendes Design und das Anstoßen an die Limits des Plans, wenn Agents in Schleifen laufen. Kakkars eigene Regel: um 18 Uhr Schluss machen und die Arbeitsgeräte im Büro lassen.

Der Einwand des Herausgebers

Gergely Orosz, der den Newsletter betreibt, ergänzt, dass sich der PR-Output branchenweit seit Januar ungefähr verdoppelt hat, dieser Fall also weit über dem Durchschnitt liegt, und dass Geschwindigkeit allein nicht beweist, dass ein Produkt erfolgreich ist. Etablierte Unternehmen, so sein Argument, sollten ihre Prozesse vorsichtiger umstellen.

Was das bedeutet, wenn Sie einen Coding-Agent auswählen

Der Gewinn kam aus dem Prozess, nicht nur aus dem Tool. Aufgeschriebener Kontext, ein automatischer Reviewer bei jedem PR und Regeln, die aus Incidents gelernt wurden, haben ebenso viel beigetragen wie das Modell.

Planen Sie die Limits ein. Selbst der höchste Claude-Plan war erschöpft, wenn Agents in Schleifen arbeiteten. Prüfen Sie also das Kontingent, bevor Sie mit nächtlichen Läufen planen.
